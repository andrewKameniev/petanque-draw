against that snapshot; line numbers are intentionally omitted in favor of
stable files, symbols, and Firebase paths.

## User-value priority

This is the recommended repair order, separate from technical severity. It
favors broad exposure, wrong official results, silent data damage, normal user
flows, and failures that are difficult to recover; the ordering is inferred
from reachable product flows because production usage telemetry was not
available.

## Critical

### CQ-01 — Portal write credential is embedded in the public bundle

- **Origin:** New.
- **Location:** `.github/workflows/deploy.yml` (`VITE_FPU_AUTH_TOKEN`),
  `src/services/portal.js` (`updatePortalTournament`),
  `src/components/Tournament.vue` (`exportTirToPortal`), and
  `src/components/partials/Ranking.vue` (`exportResults`).
- **Finding:** The Pages workflow supplies a secret through a `VITE_*`
  variable, which Vite replaces in browser code during the build. The client
  then sends that value as an `Authorization` header to Portal write endpoints;
  email allowlists in Vue only hide controls and cannot protect a credential
  already delivered to every browser.
- **Impact:** Anyone who can load the deployed assets can recover the shared
  write credential and use the authority granted to it outside the UI.
- **Fix direction:** Move Portal writes behind an authenticated server-side
  boundary, authorize the user and tournament there, remove the token from the
  client build, and rotate the current credential after deployment changes.
- **Coverage gap:** Portal tests inject placeholder tokens but do not assert
  that production client artifacts are credential-free.
- **Reproduction (2 sentences):** Build locally with
  `VITE_FPU_AUTH_TOKEN=AUDIT_SENTINEL` and search the generated `dist` assets
  for `AUDIT_SENTINEL`. The marker appears in browser-delivered code used to
  construct the Portal authorization header, proving a production value would
  be public as well.

### CQ-02 — Email lookup registry is enumerable and can be pre-claimed

- **Origin:** Expanded former finding 27.
- **Location:** `database.rules.json` at `emails` and `emails/$emailKey`,
  `src/stores/main.js` (`setUser`), and
  `src/services/archive-collaboration.js` (`addCollaborator`).
- **Finding:** Every authenticated account may read the whole email-to-UID map.
  It may also write any absent email key because the rule neither binds the key
  to `auth.token.email` nor requires the value to equal `auth.uid`.
- **Impact:** An account can enumerate registered addresses or reserve a future
  address, after which an invitation for that address grants tournament access
  to the wrong UID and the real user cannot replace the existing mapping.
- **Fix direction:** Make this a server-managed identity lookup, or enforce
  ownership of both key and value with rules backed by verified authentication
  claims; clients should never receive the collection-wide mapping.
- **Coverage gap:** Collaboration tests mock trusted lookup results, and the
  repository has no Firebase Rules Emulator tests for registry integrity.
- **Reproduction (2 sentences):** In the Firebase Emulator, authenticate a
  fake ordinary account and write its UID to an absent mapping for a different
  fake email address. Invite that address from a second fake account and
  observe that collaboration access is assigned to the UID that pre-claimed
  the mapping.

## High

### CQ-03 — Public TIR playoff renders participant names as raw HTML

- **Status:** Resolved and merged on 2026-08-09 in
  [PR #198](https://github.com/andrewKameniev/petanque-draw/pull/198).
- **Origin:** Former finding 10, still valid.
- **Location:** `src/components/tir/TirPublicView.vue` (`formatName` and its two
  `v-html` bindings).
- **Finding:** `formatName` interpolates a participant-controlled name into an
  HTML string and the template renders it with `v-html` without sanitization.
  Vue escaping is therefore bypassed on the public playoff page.
- **Impact:** A stored participant name can inject markup and browser-active
  attributes into every viewer's public page.
- **Fix direction:** Render surname and remaining name as ordinary Vue text
  nodes in separate elements; no HTML parser or sanitizer is needed for the
  current bold-surname presentation.
- **Coverage gap:** TIR tests cover playoff state and scoring but not safe DOM
  rendering of untrusted participant names.
- **Reproduction (2 sentences):** In a local test tournament, name a TIR
  participant `<strong data-audit="name">Audit</strong>` and advance that
  participant to a public playoff match. Open the public TIR view and inspect
  the DOM, where the name becomes a `strong` element instead of literal text.

### CQ-04 — A reachable later Swiss round can crash the pairing rollback

- **Origin:** Former finding 11, still valid.
- **Location:** `src/services/draw.js` (`drawSwissRound`, expansion rollback
  using `teamsDrawed`).
- **Finding:** When pairing expansion retries exceed the number of already
  drawn pairs, the rollback loop indexes before the start of `teamsDrawed` and
  unshifts `undefined`. The next pairing attempt dereferences
  `undefined.opponents` instead of returning the supported `cantDraw` result.
- **Impact:** A valid eight-team tournament can become unable to draw its next
  round after six completed rounds.
- **Fix direction:** Bound rollback by the number of available pairs, keep the
  pairing state transactional, and add the reproduced tournament history as a
  regression fixture.
- **Coverage gap:** Existing exhaustion tests cover the clean `cantDraw` case,
  not this partial-rollback state.
- **Reproduction (2 sentences):** With rated teams A–H, play six rounds and
  make the second-listed team win these pairings: `A-E/B-F/C-G/D-H`,
  `E-H/F-G/A-D/B-C`, `G-H/C-F/D-E/A-B`, `H-F/G-A/E-C/D-B`,
  `F-E/H-A/C-D/G-B`, and `F-A/E-B/H-C/G-D`. Draw round 7 and observe
  `drawSwissRound` fail while reading `opponents` from an undefined team.

### CQ-05 — Poules remains selected after the team count becomes invalid

- **Status:** Resolved and merged on 2026-08-09 in
  [PR #197](https://github.com/andrewKameniev/petanque-draw/pull/197).
- **Origin:** Former finding 4, corrected and still valid.
- **Location:** `src/components/partials/SetupCard.vue` (Poules option and draw
  button) and `src/services/draw.js` (`createPoules`).
- **Finding:** The UI hides the Poules radio unless the count is divisible by
  four, but it does not reset an already-selected `tournament.system` after a
  team is added or removed. `createPoules` then uses the fractional
  `teamsCount / 4` as a traversal boundary and eventually accesses a missing
  group.
- **Impact:** A normal pre-start edit can make the first draw throw instead of
  showing an actionable validation message.
- **Fix direction:** Validate the invariant at the draw command boundary and
  either keep the current setup unchanged with an error or explicitly reset
  the system when the count changes.
- **Coverage gap:** Poules tests start from already valid four-team groups and
  do not cover setup changes after system selection.
- **Reproduction (2 sentences):** Create eight teams, select Poules, and then
  add a ninth team so the radio disappears while the Poules settings remain
  visible. Click **Draw first round** and observe `createPoules` fail while
  pushing into a missing group.

### CQ-06 — Public TIR winner ignores the persisted tie-break winner

- **Status:** Resolved and merged on 2026-08-09 in
  [PR #200](https://github.com/andrewKameniev/petanque-draw/pull/200).
- **Origin:** New.
- **Location:** `src/services/tir.js` (`getMatchWinner` and
  `updateTirMatchFromScores`) and `src/views/Public.vue` (`winnerTeam`).
- **Finding:** The TIR service correctly resolves equal final scores through
  `tieWinner` and persists `match.winner`, but the public winner card ignores
  that value and recomputes from `score1 > score2`. Every tied final therefore
  selects player 2 in the public header, even when player 1 won the tie-break.
- **Impact:** The most prominent public result can contradict the official
  playoff record.
- **Fix direction:** Use the canonical persisted winner, with a service helper
  as the compatibility fallback for older records.
- **Coverage gap:** Service tests cover TIR tie-breaks, but no public-view test
  covers an equal-score final.
- **Reproduction (2 sentences):** Complete a local TIR final with equal totals,
  choose player 1 as the tie-break winner, and finish the tournament. Open the
  public page and observe that the winner card names player 2 while the stored
  final names player 1.

## Medium

### CQ-07 — Admin live sync ignores remote deletion of competition state

- **Status:** Resolved and merged on 2026-08-09 in
  [PR #196](https://github.com/andrewKameniev/petanque-draw/pull/196).
- **Origin:** New, discovered while rechecking former finding 20.
- **Location:** `src/services/tournament-sync.js`
  (`applyCompetitionValue`, `mergeGames`, `mergeBracketPlayoff`, and
  `mergePlayoff`).
- **Finding:** Specialized subscriptions merge truthy values for `games`,
  `cadrage`, `playOffBracket`, `tirPlayoff`, and `teamPlayoff`, but a Firebase
  deletion arrives as `null` and is ignored. Local state can therefore retain a
  stage or round that another authorized client removed.
- **Impact:** Clients disagree about the active tournament phase and a stale
  client can later write obsolete state back to Firebase.
- **Fix direction:** Treat `null` as an explicit deletion, distinguish it from
  `undefined`, and test deletion for every specialized subscription path while
  preserving the recent-local-write guard.
- **Coverage gap:** Sync tests cover value merges and null safety, but not
  deletion convergence between two clients.
- **Reproduction (2 sentences):** Open one Emulator-backed tournament in two
  authorized clients and remove its bracket or games node from client B through
  the normal restore flow. Client A remains subscribed but continues showing
  the deleted state because the null snapshot is ignored.

### CQ-08 — Shared historical-result edits write under the collaborator UID

- **Status:** Resolved and merged on 2026-08-09 in
  [PR #199](https://github.com/andrewKameniev/petanque-draw/pull/199).
- **Origin:** New.
- **Location:** `src/components/partials/Results.vue` (`persistToFirebase`).
- **Finding:** The results editor bypasses the owner-aware tournament sync
  service and updates `${store.user.uid}/tournaments/` directly. For a shared
  tournament, `store.user.uid` is the collaborator rather than the record's
  `_ownerUid`.
- **Impact:** The UI reports success while the owner and public result remain
  unchanged, and an unintended tournament copy may be created under the
  collaborator account.
- **Fix direction:** Move the edit into an owner-aware service operation that
  writes only the changed game and recalculated team fields atomically.
- **Coverage gap:** Results tests cover selection helpers but not a mounted
  shared-tournament persistence path.
- **Reproduction (2 sentences):** In the Emulator, invite an admin collaborator
  to a groups tournament and edit a finished result from the collaborator's
  Results tab. The success message appears, but the owner's record is unchanged
  while the write targets the collaborator's tournament path.

### CQ-09 — Restoring an unscored round removes completed-round history

- **Origin:** Former finding 8, expanded with the normal production failure.
- **Location:** `src/stores/main.js` (`addRoundToGames` and `restoreRound`) and
  `src/services/draw.js` (`saveResultsForRound`).
- **Finding:** Drawing a round records lanes but does not add opponents;
  opponents are added only when results are saved. `restoreRound` nevertheless
  removes one opponent from every team after deleting the unscored active
  round, so it rolls back history belonging to the preceding completed round;
  it also throws on legacy teams without an `opponents` array.
- **Impact:** Swiss rematch prevention and live ranking state become incorrect,
  and some legacy tournaments cannot restore a round at all.
- **Fix direction:** Rebuild derived opponent and lane history from the
  remaining finished games, and normalize missing per-team arrays when records
  enter the application.
- **Coverage gap:** The Group B restore test manually adds opponent entries for
  the unscored round, which does not match the production lifecycle.
- **Reproduction (2 sentences):** Finish round 1 of an even-team Swiss
  tournament, draw round 2 without entering scores, and choose **Restore
  round**. Inspect the teams afterward and observe that each round-1 opponent
  was removed even though only unscored round 2 was deleted.

### CQ-10 — Repeated round-robin pairing edits the first match

- **Status:** Resolved and merged on 2026-08-09 in
  [PR #195](https://github.com/andrewKameniev/petanque-draw/pull/195).
- **Origin:** Former finding 21, still valid.
- **Location:** `src/components/partials/Results.vue` (`saveEditedResult`).
- **Finding:** The editor receives the selected game object but searches all
  rounds from zero using only `team_1` and `team_2`, then stops at the first
  match. Multi-circle round robin legitimately contains the same oriented
  pairing more than once.
- **Impact:** Editing a later result silently overwrites an earlier round and
  recalculates standings from the wrong history.
- **Fix direction:** Carry stable round and game indexes, or a persisted match
  ID, from rendering through the edit command.
- **Coverage gap:** Multi-circle tests cover displayed results, not edit-target
  identity.
- **Reproduction (2 sentences):** Create a multi-circle round robin where A
  plays B twice with A on the same side, then finish both matches with different
  scores. Edit the later A–B result from Results and observe that the first
  A–B game is overwritten instead.

### CQ-11 — Poules round 2 trusts a complete two-game group

- **Origin:** Former finding 5, narrowed to malformed synchronized data.
- **Location:** `src/services/draw.js` (`drawPoulesRound`).
- **Finding:** Round 2 unconditionally dereferences `r1Games[0]` and
  `r1Games[1]`. A legacy or externally corrupted round with one missing group
  game passes into the draw without a shape check and crashes on `game2`.
- **Impact:** One malformed persisted group prevents the organizer from
  continuing the entire tournament.
- **Fix direction:** Validate the complete Poules round shape before mutation,
  return a stable error code, and leave the tournament recoverable.
- **Coverage gap:** Current tests cover only complete four-team Poules groups.
- **Reproduction (2 sentences):** Seed an Emulator tournament with an
  eight-team Poules first round in which one group contains only one of its two
  games, then load that tournament. Finish the available games and start round
  2, which fails when `drawPoulesRound` reads the missing second game.

### CQ-12 — Protocol place range is wrong for more than two groups

- **Origin:** Former finding 22, still valid.
- **Location:** `src/protocol-helpers.js` (`getTeamPlaceInGroups`) and its
  expectation in `src/__tests__/protocol-helpers.spec.js`.
- **Finding:** For place `p` across `g` groups, the range should start at
  `(p - 1) * g + 1`; the current non-first-place formula starts at `p * g - 1`.
  The existing test incorrectly locks in `7-8` for second place across four
  groups.
- **Impact:** Generated protocols publish incorrect shared place ranges.
- **Fix direction:** Correct the formula and replace the expectation with
  `5-8`, adding cases for three and four groups.
- **Coverage gap:** This is a case where a passing test confirms the defect
  rather than the intended domain rule.
- **Reproduction (2 sentences):** Create a tournament with four groups and
  generate a protocol containing all four second-place teams. The protocol
  labels them `7-8` instead of the correct shared range `5-8`.

### CQ-13 — Lane history misses composite games and over-rolls bye teams

- **Origin:** New.
- **Location:** `src/stores/main.js` (`saveLanesToTeams`, `shuffleLanesStore`,
  `swapLanesStore`, and `restoreRound`) and `src/services/draw.js`
  (`assignLanes`).
- **Finding:** `assignLanes` reads individual Supermêlée players from
  `team_1_players` and `team_2_players`, but persistence compares individual
  team titles only with composite display names such as `P1, P2`, so normal
  player lane history stays empty. The rollback paths also pop one lane from
  every team, including a Technical-bye team that received no lane in the
  current round.
- **Impact:** Consecutive-lane avoidance is ineffective for Supermêlée and loses
  valid history for odd-team Swiss tournaments.
- **Fix direction:** Centralize extraction of a game's participating team
  titles and update or roll back history only for players actually assigned a
  lane.
- **Coverage gap:** Lane tests manually pre-seed histories and call the pure
  allocator, bypassing store persistence and bye rollback.
- **Reproduction (2 sentences):** Draw round 1 of an eight-player Supermêlée
  tournament and observe that composite games have lanes while every
  individual player's `lanes` array remains empty. Separately, give a Swiss
  team with lane history a Technical bye and shuffle the round, then observe
  that the team's previous real lane is popped and not restored.

### CQ-14 — Team titles are normalized after validation

- **Origin:** New.
- **Location:** `src/components/partials/AddTeam.vue` (`addTeam`).
- **Finding:** Empty and duplicate checks use the raw input, but the stored
  identity uses `title.trim()`. Whitespace-only input becomes an empty title,
  and a padded form of an existing title passes the duplicate check before
  becoming an identical canonical title.
- **Impact:** Title-keyed games, opponents, rankings, and replacements become
  ambiguous without any way to distinguish the duplicate teams.
- **Fix direction:** Normalize once before all validation, reject an empty
  normalized title, and compare canonical titles consistently.
- **Coverage gap:** There is no AddTeam test for whitespace-only or padded
  duplicate input.
- **Reproduction (2 sentences):** Add a team named `Alpha`, then enter a
  second title with one leading and one trailing space around `Alpha` and
  submit it. The setup stores two teams both titled `Alpha`, making later
  title-based references ambiguous.

### CQ-15 — Replacement titles containing `/` lose keyed playoff data

- **Origin:** New.
- **Location:** `src/services/team-replacement.js` (`normalizePortalTeam`,
  `joinPath`, `renameReferences`, and `finalizeUpdates`).
- **Finding:** Portal titles containing `/` are accepted, but replacement
  updates are represented as slash-delimited Firebase paths and later read by
  splitting on `/`. A keyed placement renamed to `Alpha/Beta` exists in the
  in-memory competition but cannot be recovered through that path, so the
  generated update retains only deletion of the old key.
- **Impact:** Reloading after a replacement can silently discard the team's
  playoff placement while other references use the new identity.
- **Fix direction:** Reject Firebase-forbidden key characters at the boundary
  or stop representing arbitrary object keys as unescaped path strings.
- **Coverage gap:** Team replacement tests cover ordinary key renames and
  collisions but no delimiter-containing Portal title.
- **Reproduction (2 sentences):** In a local team-replacement fixture, replace
  a placed team with a Portal team titled `Alpha/Beta`. Apply the returned
  updates and observe that the old placement is deleted without a new keyed
  placement being persisted.

### CQ-16 — Scorer rules authorize whole competition subtrees

- **Origin:** Former finding 26, narrowed to the authorization boundary.
- **Location:** `database.rules.json` child writes for `games`, `cadrage`,
  `playOffBracket`, `tirPlayoff`, `teamPlayoff`, `roundTimer`, and `barrage`.
- **Finding:** Child rules authorize any existing collaborator and never inspect
  `role`. Score entry may be intended for scorers, but the same condition grants
  replacement or deletion of entire brackets, timers, and phase state that the
  UI reserves for owners and admins.
- **Impact:** A scorer account has materially more tournament authority than
  the product role communicates.
- **Fix direction:** Define explicit capabilities by role and path, restrict
  score writes to validated match leaves, and enforce phase-changing operations
  for owner/admin roles only.
- **Coverage gap:** There are no Rules Emulator tests for scorer-versus-admin
  permissions.
- **Reproduction (2 sentences):** In the Firebase Emulator, invite a fake
  account as `scorer` and confirm that owner-only bracket controls are hidden in
  its UI. Use that authenticated fake account to replace a bracket or timer
  subtree and observe that the current child rule accepts the write.

### CQ-17 — Scorers can start a rename that silently fails

- **Origin:** New.
- **Location:** `src/components/partials/TournamentHeader.vue`,
  `src/stores/main.js` (`changeTournamentName`), and
  `src/services/tournament-sync.js` (`syncPath`).
- **Finding:** The shared tournament header exposes rename editing without a
  role capability, and the store optimistically changes local state before
  writing. Firebase correctly rejects a scorer's root `name` write, but
  `syncPath` only logs the failure while the scorer's private user-map alias may
  still be saved.
- **Impact:** The scorer sees a successful-looking rename, the owner retains the
  old canonical name, and two labels can diverge without feedback.
- **Fix direction:** Hide or disable canonical rename without owner/admin
  capability and make failed writes roll back optimistic state with a visible
  error.
- **Coverage gap:** No mounted header test covers scorer role or a rejected
  rename write.
- **Reproduction (2 sentences):** Open an Emulator-backed shared tournament as
  a scorer, edit the heading, and save a new name. Refresh both scorer and owner
  sessions and observe that the canonical name did not change even though no
  save error was shown.

### CQ-18 — Public loading reads the full tournament record

- **Origin:** Former finding 25, narrowed because anonymous score viewing is
  intentional.
- **Location:** `database.rules.json` at `$uid/tournaments/$tid`,
  `src/services/live-tournament.js` (`reload`), and
  `src/services/db.js` (`tournamentService.getOne`).
- **Finding:** The public page initially reads and normalizes the complete
  tournament node before subscribing to a curated public field list. That node
  can include collaborator email addresses and administrative metadata that the
  public presentation never needs.
- **Impact:** Possession of a share URL exposes private collaboration metadata
  along with the intended public teams and scores.
- **Fix direction:** Publish a dedicated public projection or place public data
  under a separately readable subtree; the initial fetch must obey the same
  allowlist as live subscriptions.
- **Coverage gap:** Public-source tests verify selected subscriptions but use a
  full-record initial fixture without asserting metadata minimization.
- **Reproduction (2 sentences):** In the Emulator, create a shared tournament
  containing a fake collaborator email and open its public URL without signing
  in. Inspect the initial tournament snapshot and observe that it includes the
  collaborator record even though the page only displays public competition
  fields.

### CQ-19 — Firebase permits malformed tournament shapes and scores

- **Origin:** Former finding 28, still valid.
- **Location:** `database.rules.json` throughout writable tournament paths.
- **Finding:** The rules contain no `.validate` constraints for game fields,
  score types and ranges, statuses, required team identities, or collection
  shapes. Any writer authorized at a subtree can persist values that client
  code assumes are arrays, numbers, or complete matches.
- **Impact:** One malformed write can crash draw/ranking code or create
  long-lived disagreements between clients, and client validation cannot repair
  the trust boundary.
- **Fix direction:** Add incremental Rules Emulator-tested schemas, starting
  with match score/status leaves and phase structures used by collaborators.
- **Coverage gap:** Unit tests validate client helpers but do not execute
  `database.rules.json`.
- **Reproduction (2 sentences):** In the Firebase Emulator, authenticate an
  allowed collaborator and write a nonnumeric score or object-valued status to
  a game. Read the game back and observe that Firebase stored the malformed
  value because no validation rule rejected it.

### CQ-20 — Score-input Tab wrapping checks a class that no longer exists

- **Origin:** Former finding 9, narrowed from “navigation broken” to the custom
  wrapping behavior.
- **Location:** `src/components/partials/Games.vue` (`mounted` key handler) and
  `src/components/ui/TournamentNav.vue` (active-tab class and ARIA state).
- **Finding:** The handler requires `#tab-games.is-active`, but the nav uses
  `tournament-nav__btn--active` and `aria-selected="true"`. Native Tab still
  works, but the intended score-only cycle and final-to-first wrap never run.
- **Impact:** Keyboard-heavy score entry leaves the input sequence at its end
  instead of continuing through scores as designed.
- **Fix direction:** Prefer component state or the active tab's ARIA attribute
  over a global selector, and cover forward and reverse wrapping in a mounted
  test.
- **Coverage gap:** Existing navigation tests cover tournament tabs, not the
  document-level score-input handler.
- **Reproduction (2 sentences):** Start a round, focus the final enabled score

  to and selecting the first score because the active-tab selector never

## Low

### CQ-21 — A 0–0 draw lacks inline invalid styling

- **Origin:** Former finding 14, narrowed because final validation is correct.
- **Location:** `src/helpers.js` (`gameHasError`) and
  `src/components/partials/Game.vue` (danger class).
- **Finding:** `gameHasError` deliberately excludes equal scores when both
  normalized values are zero, while the round-completion validator rejects all
  equal scores. The command is blocked correctly, but the row-level feedback is
  inconsistent with every other draw.
- **Impact:** An organizer receives no immediate visual cue until attempting to
  finish the round.
- **Fix direction:** Distinguish two empty scores from two explicitly entered
  zero scores before applying the equal-score rule.
- **Coverage gap:** Helper tests cover nonzero equality and null values but not
  explicit zero strings/numbers from mounted inputs.
- **Reproduction (2 sentences):** Enter `0` for both teams in a non-technical
  game. The row is not highlighted as invalid, although finishing the round
  later shows the no-draw error.

### CQ-22 — TIR-only player aggregate percentage returns a dash

- **Origin:** Former finding 23, narrowed to a helper-contract defect.
- **Location:** `src/helpers-stat.js` (`calculatePlayerStat`).
- **Finding:** `allPercent` includes point and TIR attempts in its numerator and
  denominator, but its guard checks only whether point attempts exist. A player
  with only TIR attempts therefore gets a valid `tirsPercent` and an invalid
  aggregate dash; the current analysis component happens to recompute the
  aggregate independently.
- **Impact:** The exported helper is internally inconsistent and will display
  incorrect output in any consumer that trusts `allPercent`.
- **Fix direction:** Guard on the total of both throw types and add a TIR-only
  regression test.
- **Coverage gap:** Existing helper tests cover successful TIR counting but not
  its aggregate percentage.
- **Reproduction (2 sentences):** Call `calculatePlayerStat` with one completed
  successful TIR throw and no point throws under the simple system. The result
  contains `tirsPercent: 100` but `allPercent: '-'`.

### CQ-23 — Statistics score clamping can return a negative value

- **Origin:** Former finding 24, still valid at the corrupted-state boundary.
- **Location:** `src/helpers-stat.js` (`validateScore`) and
  `src/views/Stats.vue` (`updateTeamScore`).
- **Finding:** `validateScore` applies the zero lower bound before limiting the
  result to `13 - prevTotal`. If saved or concurrently edited prior values total
  more than 13, the second clamp produces a negative score that the caller
  assigns directly.
- **Impact:** A recoverable malformed statistics game can be made more corrupt
  by ordinary editing.
- **Fix direction:** Clamp the final result on both bounds and validate loaded
  score arrays before editing.
- **Coverage gap:** Validation tests cover ordinary caps, not a pre-existing
  total above the cap.
- **Reproduction (2 sentences):** Call `validateScore(2, [7, 7, 0], 2, 1)` or
  load the equivalent local saved game. The helper returns `-1`, which
  `updateTeamScore` assigns to the selected team.
